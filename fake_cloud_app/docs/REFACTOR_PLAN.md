# 假云控重构计划

## Phase 1

目标：

- 先把项目入口、文档、边界抽离出来
- 不打断当前 `18080` 服务

结果：

- 已有 `fake_cloud_app/`
- `app/main.py` 可以收缩成兼容入口

## Phase 2

目标：

- 拆 store 里的大一统逻辑

建议动作：

1. 先拆只读查询和写入命令
2. 再拆领域：
   - auth
   - station
   - camera
   - pairing
   - message
   - playback

## Phase 3

目标：

- 把浏览器云平台完全从假云控中移走

建议动作：

1. 浏览器云平台只调用明确的服务接口
2. 不再直接依赖 `kv_state` 的杂糅结构
3. live / playback 适配层单独规划，为后续接 ZLMediaKit 预留边界

## Phase 4

目标：

- 引入更稳的持久化模型

建议动作：

1. 给账户、基站、摄像头、绑定关系做独立仓储层
2. 给 request log 做归档和裁剪
3. 给消息、回放索引做可维护的数据访问层

## Phase 5

目标：

- 为“新增基站、账户注册、账户绑定、摄像头配网”做正式建模

建议动作：

1. 明确账户注册与默认测试账户的分离
2. 明确基站归属变更流程
3. 明确摄像头配网、删机、重配、改名的状态机
